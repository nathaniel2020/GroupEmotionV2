# 群体情感视频项目轻量化重构方案

## 1. 目标

本项目不是去“删减版复刻”原仓库，而是明确做一次工程策略切换：

- 从“全链路自动化优先”切换到“标注主链路稳定优先”
- 从“模块多、状态多、排障面大”切换到“流程短、记录全、问题可定位”
- 从“默认复杂能力都上线”切换到“只保留当前科研推进真正需要的能力”

## 2. 原项目哪些要暂时拿掉

参考项目里这些能力本身没问题，但不适合当前初始化版本：

- 自动 query planner
- 多平台采集编排
- 多数据库拆分
- 长视频复杂事件 proposal
- 多智能体并行标注
- 大量导出与 lineage 分层

这些能力共同的问题不是“无用”，而是：

- 上线面过宽
- 问题定位链条太长
- 每次改 prompt 或模型都可能波及多个阶段
- 当前瓶颈已经转移到“调用是否稳定、标注是否可信、失败是否可复盘”

## 3. 新版最小主链路

新版只保留四步：

1. `sample ingest`
   外部准备好样本清单，每条样本对应一个 `sample.json`。
2. `annotate`
   调一次主模型，输出严格 JSON。
3. `review gate`
   根据置信度、证据充分性和字段冲突决定 `approved` 或 `needs_review`。
4. `export`
   仅导出通过 gate 的样本。

对应的状态机建议简化为：

```text
pending -> running -> approved
                 -> needs_review
                 -> failed
```

## 4. 如何在简化流程时保证标注质量

重点不是重新堆复杂度，而是把质量检查放到更短的主链路里。

### 4.1 一个主模型，三个硬约束

- 必须输出结构化 JSON
- 必须给出字段级证据
- 必须给出字段级置信度

如果这三点做不到，后续任何多智能体或多轮讨论都只是放大不稳定性。

### 4.2 回流条件前置

以下情况直接进入 `needs_review`：

- 关键字段缺失
- 证据为空或明显不支持结论
- 总体置信度低于阈值
- 模型输出无法解析
- 不同字段之间逻辑冲突

### 4.3 人工复核不要全量做

建议只保留两类人工复核：

- 风险驱动复核：所有 `needs_review`
- 抽样复核：所有 `approved` 中随机抽样 10%

这样能在不拖垮产能的情况下获得稳定的质量反馈。

### 4.4 质量闭环记录到样本级

每个样本至少保存：

- 原始输入摘要
- Prompt 版本
- 模型名
- 原始响应路径
- 解析结果
- gate 决策
- gate 原因

这样后续才能做 prompt ablation、模型对比和失败回放。

## 5. 日志系统重构思路

原项目最大的问题之一不是“没有日志”，而是“缺少能定位模型调用问题的日志”。

新版建议把日志拆成四层：

- `manifest.json`
  记录一次 run 的配置快照、命令、时间、输入文件。
- `events.jsonl`
  记录阶段流转和业务事件。
- `llm_calls.jsonl`
  记录每次模型调用的摘要：模型、延迟、状态、token、artifact 路径。
- `errors.jsonl`
  记录所有失败及堆栈摘要。

每次模型调用再额外保存：

- `request.json`
- `response.json`

这样日志既能快速扫摘要，也能下钻到单次请求。

## 6. 多模态大模型调用的简化策略

### 6.1 默认不要直接发本地原视频

这是当前最重要的工程原则。原因很直接：

- 文件体积大
- OpenAI-compatible 服务对视频输入支持差异很大
- `file://`、`data:`、本地 HTTP 暴露三种方式都可能踩坑
- 一旦失败，排查成本远高于图像输入

因此建议默认策略是：

- 发送关键帧
- 发送 transcript 摘要
- 可选发送一个远程视频 URL

只有当模型和服务端都稳定支持视频时，再打开视频模式。

### 6.2 统一成一个客户端

不要在脚本里散落 `requests`、`curl`、SDK 混用。统一要求：

- 一个客户端封装所有调用
- 一个重试策略
- 一个日志落盘格式
- 一个错误上下文结构

### 6.3 先做“可恢复”，再做“更聪明”

重试只针对明确的瞬时错误：

- 超时
- 429
- 5xx
- 网络连接失败

而 JSON 解析失败、字段缺失、证据不足不应盲目无限重试，应直接进入 review 或失败队列。

## 7. 当前建议的仓库骨架

```text
configs/
docs/
prompts/
scripts/
src/group_emotion_video/
data/
runtime/
```

对应代码模块只保留：

- `config.py`
- `logging_utils.py`
- `llm.py`
- `pipeline.py`
- `cli.py`

## 8. 下一阶段建议

等这一版稳定后，再逐步补：

1. `sample.json` 批处理
2. 裁决模型二次复核
3. 质量报表
4. 导出格式
5. 采集和预处理模块

先把最短主链路跑通，后面的复杂度才有加回来的资格。
