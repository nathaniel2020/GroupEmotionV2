# 013.02 轻量化重构实施说明

## 1. 当前实现目标

本仓库已经落地一条面向 `10W` 级 CLIP 生产的轻量化流水线：

```text
prepare-reference
-> seed-queries
-> crawl
-> preprocess
-> annotate
-> export
```

设计原则：

- 外部参考数据只解析一次，运行期全部读取本地 JSON。
- 越靠前越便宜，越靠后越重。
- 原视频只做临时资产，不长期保留。
- accepted clip 必须通过严格 schema 校验。
- 下载并发和 LLM 并发都走配置，不把并行写死在代码里。

## 2. 参考数据准备

`prepare-reference` 负责一次性固化两份文件：

- `data/reference/query_seed_catalog.json`
  - 来源：`原子情感因素.xlsx`
  - 只读取 `情感因素` sheet
  - 使用 `情境场景` 和同一行 `触发事件`
  - 跳过章节标题行、说明行和空行
- `data/reference/annotation_domains.json`
  - 来源：`013.01 video/doc/标注字段.xlsx`
  - 统一冻结字段类型、必填约束、枚举值域、数值范围
  - `group_emotion` 额外合并本地冻结标签种子

运行期若这两份文件缺失，流程直接失败，不做回退。

## 3. Query 生成

运行期 query 不再读 Excel，而是只读 `query_seed_catalog.json`。

每个有效 seed 行固定生成 2 到 3 条 query：

- `scene_text`
- `scene_text + 现场`
- `scene_text + trigger_core`

调度策略采用简单 round-robin，状态存到 `runtime/index.sqlite` 的 `queries` 表。

## 4. B 站采集与并行下载

当前实现仅支持 B 站。

### 4.1 元信息保留

每个候选视频统一映射并落盘 `video_meta.json`，保留：

- 基础标识：`video_uid`, `platform`, `bvid`, `url`, `webpage_url`
- 内容元数据：`title`, `uploader`, `publish_time`, `duration_sec`, `description`, `cover_url`
- 辅助信号：`tags`, `categories`, `view_count`, `like_count`, `comment_count`, `play_count`, `danmaku_count`, `type`
- 溯源字段：`query_id`, `scene_text`, `trigger_text`, `source_excel_row`
- 运行状态：`subtitles_available`, `rights_status`, `download_status`, `reject_reason`, `retention_status`, `accepted_clip_count`

### 4.2 下载前筛选

当前固定拒绝规则：

- `duration < 15s`
- `duration > 20min`
- 缺失 `bvid/title/url/duration` 任一核心字段
- enrich 后权限受限、格式不可用、体积超阈值

### 4.3 并发模型

- search：按 query 串行推进
- enrich：线程池并行，受 `crawl.enrich_workers` 控制
- download：线程池并行，受 `crawl.download.workers` 控制
- 同一 host 的并发下载：受 `crawl.download.max_inflight_per_host` 控制
- 同一 `bvid` 不会重复入库和重复下载

## 5. 切分、过滤与文件保留策略

### 5.1 切分

当前实现两种模式：

- 有字幕：按字幕片段聚合到 `8-15s` 窗口
- 无字幕：按 `12s` 窗口、`2s` overlap 粗切

### 5.2 过滤

L1 过滤：

- 过短
- 过长

L2 过滤：

- 群体信号弱
- 情绪信号弱

当前 L2 使用标题、描述、标签、字幕的轻量启发式，不默认启用额外 LLM 过滤。

### 5.3 工件与清理

accepted clip 保留：

- `clip.mp4`
- `subtitle_or_text.json`
- `keyframes_manifest.json`
- `clip_manifest.json`

rejected clip 只保留：

- `runtime/artifacts/rejections/clips/<clip_uid>.json`

raw source video 在视频处理完成后统一删除：

- 整视频 rejected：只保留 `video_meta.json` 与 rejection 记录
- 有 accepted clip：clip 工件落盘后删除 raw video

## 6. 标注与值域约束

输出保持兼容 `013.01`：

- `agent_outputs`
- `final_annotation`
- `field_confidence`
- `quality_flags`

`final_annotation` 使用扁平 dotted-key，固定 22 个字段：

- `scene_description`
- `group_size_estimate`
- `valence`
- `arousal`
- `trigger_event_type`
- `trigger_event_description`
- `group_behavior_type`
- `group_behavior_description`
- `group_emotion`
- `behavior_sync`
- `heterogeneity.dominant_proportion`
- `heterogeneity.minority_dissent`
- `heterogeneity.alignment_type`
- `appraisal.novelty`
- `appraisal.goal_congruence`
- `appraisal.agency`
- `contagion.origin`
- `contagion.spread_pattern`
- `temporal.trajectory_type`
- `emotion_layers.layer_consistency`
- `social_structure.norm_context`
- `social_structure.ingroup_salience`

校验规则：

- `enum` 必须精确命中本地冻结值域
- `valence/arousal` 必须是 `1..9` 整数
- `field_confidence` 必须在 `0..1`
- `trigger_event_description` 在 `trigger_event_type != none` 时必填
- `group_emotion` 必须命中冻结 catalog

只允许安全归一化：

- 去空白
- 数字字符串转数值
- 解包 `{"value": ..., "confidence": ...}`

不做语义近义词映射。

rejected-only 哨兵值只允许出现在 `annotation_status = rejected`：

- `group_size_estimate = single | none`
- `group_behavior_type = none`
- `group_emotion = none`

accepted clip 若未通过 schema 校验，则标为 `failed`，不会进入导出。

## 7. LLM 并发控制

LLM 并发不是各模块各自开线程，而是统一走全局闸门。

关键配置：

- `llm.parallel.enabled`
- `llm.parallel.max_inflight_requests`
- `llm.parallel.acquire_timeout_sec`

语义：

- `enabled = false` 或 `max_inflight_requests = 1` 时，所有 LLM 请求串行
- `enabled = true` 时，所有 stage 共用一个 `BoundedSemaphore`

因此：

- `annotation.clip_workers` 控制并行处理多少个 clip
- `llm.parallel.max_inflight_requests` 控制同时打到模型服务的真实请求数

默认 smoke profile：

- `model = gemini-3.1-pro-preview`
- `base_url = https://yunwu.ai/v1/`
- API key 通过环境变量注入，不写入受跟踪配置

## 8. 存储结构

索引层：

- `runtime/index.sqlite`
  - `queries`
  - `videos`
  - `clips`
  - `annotations`
  - `download_events`

工件层：

- `runtime/artifacts/videos/`
- `runtime/artifacts/clips/`
- `runtime/artifacts/annotations/`
- `runtime/artifacts/rejections/`
- `runtime/exports/`

accepted clip 导出时包含：

- clip 视频
- `video_meta.json`
- `clip_manifest.json`
- `annotation.json`
- `annotation_domains.json`

不导出 raw source video。

## 9. 运行方式

```bash
python scripts/run_pipeline.py prepare-reference
python scripts/run_pipeline.py seed-queries
python scripts/run_pipeline.py crawl
python scripts/run_pipeline.py preprocess
python scripts/run_pipeline.py annotate
python scripts/run_pipeline.py export
```

或：

```bash
python scripts/run_pipeline.py run --steps prepare-reference,seed-queries,crawl,preprocess,annotate,export,status
```
