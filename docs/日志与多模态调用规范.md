# 日志与多模态调用规范

## 1. 运行日志最小标准

每次执行命令必须生成一个 `run_id`，并在 `runtime/runs/<run_id>/` 下保存：

- `manifest.json`
- `events.jsonl`
- `llm_calls.jsonl`
- `errors.jsonl`
- `run.log`

额外要求：

- 任何异常都必须写入 `errors.jsonl`
- 任何模型调用都必须写入 `llm_calls.jsonl`
- 任何 `needs_review` 决策都必须在 `events.jsonl` 里可检索

## 2. 单次 LLM 调用需要保存什么

每次调用都要有一个 `call_id`，并保存到：

```text
runtime/runs/<run_id>/llm/<call_id>/
  request.json
  response.json
```

摘要字段至少包含：

- `call_id`
- `sample_id`
- `model`
- `base_url`
- `status`
- `latency_sec`
- `attempt`
- `prompt_path`
- `response_path`
- `error_type`

## 3. Prompt 与模型版本管理

建议把下列信息一并落盘：

- `prompt_name`
- `prompt_version`
- `config_hash`
- `model`

否则后面无法回答“为什么同一个样本两周后结果不同”。

## 4. 多模态输入优先级

建议优先级如下：

1. 关键帧
2. transcript / OCR / 外部上下文
3. 远程视频 URL
4. 本地原视频直传

本地原视频直传放到最后，不是因为它不先进，而是它最不稳定。

## 5. 失败分类

建议按四类记录：

- `transport_error`
  网络、超时、连接失败。
- `provider_error`
  服务端 4xx/5xx。
- `parse_error`
  模型返回无法解析为 JSON。
- `quality_gate_error`
  JSON 可解析，但字段缺失、证据不足、置信度过低。

只有前两类适合自动重试。
